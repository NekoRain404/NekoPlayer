# NekoPlayer 首个可播放版本设计

状态：用户已于 2026-10-21 确认，进入实现。

## 目标与范围

将现有启动窗口推进为能播放本地视频的桌面播放器。技术选择保持 C++20、Qt 6 和单一 libmpv 内核，优先验证稳定播放与常用操作。

当前开发环境为 Linux / Wayland，存在 XWayland、Xvfb、Qt 6.12.0、mpv 0.41.0 和 FFmpeg。首轮构建与实机验收以本机 Linux 为准；组件尽量使用跨平台 API，Windows 构建、安装包及平台专项适配放在后续阶段。本设计不承诺首版即具有完整 PotPlayer 功能。

首版包含：

- 文件菜单或 Ctrl+O 打开单个本地媒体文件；支持命令行路径和拖放。
- 嵌入窗口内的视频画面及正常音频输出。
- 播放/暂停、停止、进度显示与定位、音量和静音。
- 空格切换暂停，左右方向键前后跳转 5 秒，上下方向键调整音量，F/双击切换全屏，Esc 退出全屏。
- 文件名、时间、播放状态与错误反馈；文件结束后保留可再次操作的界面。
- 全屏时隐藏菜单和控制栏，鼠标活动时显示控制栏，闲置后自动隐藏；退出全屏恢复窗口状态。

播放列表、字幕/音轨管理、偏好设置、主题系统、HDR 和滤镜作为后续里程碑。首版不设计尚无用途的插件或多内核抽象。

## 渲染方案选择

| 方案 | 优点 | 代价 | 本阶段选择 |
| --- | --- | --- | --- |
| Qt Widgets + QOpenGLWidget + libmpv render API | 延续现有骨架；菜单和桌面控件直接；在 Qt 管理的窗口内绘制 | 必须管理 OpenGL 上下文、回调与释放顺序；需要验证合成开销 | 推荐 |
| Qt Quick + MpvQt | 可参考 Haruna；适合定制动效和界面 | 引入 QML 与额外封装；现有 FBO 路径同样受 OpenGL 限制 | 暂不引入 |
| 原生窗口 ID 交给 mpv 绘制 | 部分平台上容易快速得到画面 | 嵌入能力和覆盖控件受窗口系统约束，Wayland 尤其需要单独处理 | 暂不采用 |

首版使用默认 render API 模式，不启用 advanced control，避免在尚未需要时承担其额外线程时序约束。以已安装 mpv 0.41.0 的头文件为准。

## 组件与数据流

- `MpvController`：QObject，拥有 mpv client handle；提供异步加载、暂停、停止、定位和音量接口；消费 mpv 事件并发出 Qt 状态信号。该对象生命周期长于视频表面的 render context。
- `VideoWidget`：QOpenGLWidget，拥有 mpv render context；负责 GL 初始化、物理像素尺寸的帧缓冲绘制、更新回调及上下文释放，不拥有播放业务状态。
- `MainWindow`：拥有上述组件以及菜单、控制栏和共享 QAction，协调打开文件、拖放、快捷键和全屏。通过控制器状态更新界面。
- 后端初始化诊断保留为独立无画面模式，继续禁用用户配置与脚本，使用 null 输出；正常播放器启用实际音视频输出。

UI 操作 → 控制器提交异步命令 → mpv 执行 → 唤醒回调排入 Qt 事件队列 → 读取事件 → 状态信号更新 UI。渲染更新回调单独请求 VideoWidget 重绘。

不以定时查询代替事件同步。观察 time-pos、duration、pause、volume、mute 和播放空闲状态；利用文件加载/结束事件更新文件状态。读取到属性不可用时清理对应 UI 状态，不沿用上个文件的时间。

## 线程与生命周期

GUI 和 QOpenGLWidget 的绘制在 Qt 对应线程执行。mpv 的唤醒与渲染更新回调只安排 Qt 队列任务，不直接操作控件，不在回调里执行可能阻塞的 mpv API。

销毁流程必须避免仍在执行的回调接触已销毁对象：先停止接收交互，撤销回调并处理其在途生命周期，销毁对象时取消以该 QObject 为接收上下文的排队任务；在正确且 current 的 OpenGL context 中释放 mpv render context，最后销毁 client handle。

处理 Qt context 的 aboutToBeDestroyed 和窗口退出；释放入口可重复调用而不重复释放。全屏转换保留同一个 VideoWidget 的父子结构，尽量减少 context 重建。实际发生 context 重建时重新创建 render context，并通过测试核对播放是否能继续。

绘制使用 devicePixelRatioF 对应的实际帧缓冲尺寸。隐藏/最小化时采用 render API 支持的跳过绘制方式或必要的离屏处理，避免让 mpv 等待不会发生的可见窗口重绘。

## 交互与失败处理

菜单和快捷键共享 QAction。进度拖动期间显示用户选择的位置，释放后发起绝对定位；后台位置更新不抢占正在拖动的滑块。媒体时长未知或不可定位时禁用绝对定位。

打开新文件替换当前媒体。首版不把多文件拖放隐式变成播放列表；遇到多个文件时给出只支持单文件的提示。通过结构化参数传递路径，支持空格、中文和特殊字符。

空闲时暂停、定位等无效操作禁用。媒体结束后清空播放中的状态，保留文件名以便用户理解最后播放的内容；重新打开文件可继续使用。停止操作清理时间和活动播放状态。

所有 libmpv 关键调用检查返回值；异步命令接收结果后报告失败。打开失败显示可理解的错误，窗口继续可操作。OpenGL 或 render context 初始化失败时明确显示画面初始化失败，不伪装为正常播放。

正常播放显式禁用 mpv 自动加载用户配置、脚本、OSC 和默认键绑定，由应用统一处理交互。首版输出以 SDR 正确呈现为验收目标；可请求自动硬解，但不把请求成功当作硬解已实际使用。

## 验收与验证

1. debug 与 ASan/UBSan 构建成功，现有后端初始化检查保留。
2. 用 FFmpeg 生成短测试视频，在真实 OpenGL 环境或 Xvfb 的可用软件 OpenGL 下验证加载、时间推进、暂停后位置稳定、恢复与定位、结束事件及退出释放。自动化音频使用 null 输出，实际桌面播放单独验证声音。
3. Qt 测试验证控制器状态、错误路径和 QAction 行为，先写能观察到缺失行为的失败用例，再实现对应功能。渲染集成检查确认收到实际视频帧，并检查非全黑的已知测试图像，不能仅凭窗口出现判定画面正常。
4. 检查中文/空格路径、无效文件、连续切换文件、播放中关闭、停止后重新打开，以及多次暂停/定位。
5. 在实际桌面或支持 OpenGL 的测试显示上验证窗口缩放、全屏切换和恢复；无法覆盖的高 DPI、不同显卡或窗口系统条件明确记录。
6. Qt offscreen 平台不支持 QOpenGLWidget 时，只把它用于非 GL 组件检查；完整窗口测试放到支持 OpenGL 的显示环境，不把跳过画面验证算作通过。
