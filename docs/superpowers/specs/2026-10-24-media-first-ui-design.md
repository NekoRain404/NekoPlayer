# NekoPlayer 媒体优先 UI 视觉系统

## 背景与问题

当前界面已具备播放、最近媒体、播放列表和多主题等基础结构，但整体仍像功能控件的集合：菜单栏、视频画布、欢迎卡片、常驻传输栏和状态栏彼此分层；深浅主题都大量使用描边、圆角和强调色，控件间距与文字层级也不够统一。首页截图还显示，平台标准图标与自定义按钮风格不一致。

这次改版追求 Apple 产品常见的克制、清晰和细节一致性，不仿制 macOS 窗口外壳，不复制 PotPlayer，也不改变播放器业务。首轮只建立可复用视觉基础并应用到主窗口现有表面；首页信息结构、播放中布局和偏好设置在后续独立阶段处理。

## 目标

- 建立一致的颜色、文字、间距、形状、图标和交互状态规则；深色、浅色和跟随系统三种主题都保持清晰层级。
- 主窗口的菜单、欢迎区域、播放列表和传输栏呈现为同一产品，而不是相互独立的默认 Qt 控件。
- 减少不必要的边框、重圆角和大面积强调色；重点操作清楚但不过度突出。
- 保留现有 Qt Widgets、QAction、libmpv、Wayland 优先渲染路径、窗口装饰和所有播放行为。
- 所有普通手写代码文件不超过 500 行；主窗口协调代码继续按现有 800 行例外管理，新增视觉逻辑不得继续膨胀该文件。

## 非目标

- 不迁移 Qt Quick，不替换 libmpv，不修改硬件解码、HDR、音视频同步、队列或媒体状态。
- 本阶段不重新设计首页媒体库信息架构、播放中覆盖控制、全屏自动隐藏、mini-player 或设置对话框；这些是后续阶段。
- 不仿制 macOS 标题栏、交通灯按钮或专有图标；不要求系统字体或平台控件在 Linux 上伪装成 macOS。
- 不增加主题种类、皮肤系统、用户自定义 CSS 或动画框架。

## 视觉规则

1. **层级**：视频画面是播放态的主内容；主操作、次操作和辅助信息各有稳定层级。空闲态以简洁的媒体入口为中心，弱化说明性文字。
2. **颜色**：用语义角色表达画布、主表面、浮层、主/次文字、分隔线、强调色、焦点和禁用态。强调色只用于当前选择、主要动作和必要反馈；边框仅在帮助区分层级或焦点时出现。
3. **排版**：沿用 Qt 当前平台的 UI 字体和中文回退，按标题、分组、正文、辅助信息建立有限字号/字重层级。时间读数可继续使用等宽数字，不把全界面做成 monospace。
4. **节奏与形状**：采用 4 px 基础、8 px 主节奏；容器和按钮有明确但克制的圆角等级，不给每个控件都加独立卡片边框。保留现有至少 32 px 的传输操作点击区域。
5. **图标与状态**：一个表面内使用一致的线条/填充风格和尺寸；避免跨主题不一致的系统小图标。hover、pressed、checked、selected、focused、disabled 状态必须彼此可辨，键盘焦点清楚可见。
6. **主题**：Dark 和 Light 使用同一语义角色映射到各自色板；System 保留 Qt/桌面提供的系统调色板行为。高对比文本、焦点和选中态在两种自定义主题中都需满足可读性。

## 第一阶段范围：视觉基础与主窗口现有表面

- 将视觉值从散落的样式字符串中收敛为小型、无业务依赖的 token/value 模块；由主题映射生成调色板与样式，不让播放控件自行定义品牌色。
- 统一主窗口已有 menu/status、WelcomePanel、PlaylistPane、TransportBar 的表面、文字层级、间距、分隔、按钮状态和焦点呈现。
- 继续由现有 QAction 提供菜单、快捷键和传输动作的唯一行为来源；样式改动不得复制或重绑播放命令。
- 将图标视觉差异纳入同一主窗口规则；采用 Qt Widgets 可稳定绘制、适配高 DPI 的资源或矢量图标，不依赖平台 emoji/彩色位图。
- 把调色板/token 定义、样式生成与组件行为分开；必要时拆分现有 `appearancepreferences.cpp`，保持各文件职责单一并满足行数限制。

本阶段只调整表现和表面层级，不重排主窗口业务组件，不改变现有快捷键、按钮可用性、播放列表编辑、定位、全屏状态或设置语义。

## 后续阶段边界

1. **首页与媒体历史**：重新平衡空状态、最近媒体、打开入口和拖放提示；保持最近历史数据及恢复逻辑不变。
2. **播放态、控制栏与播放列表**：让画面成为视觉中心，弱化常驻 chrome；评估轻量覆盖控制与播放列表展开/收起的整体层级，继续复用现有动作和全屏生命周期。
3. **偏好设置与辅助对话框**：统一页面导航、控件状态、帮助文本、按钮本地化和中英文运行时刷新。

每个后续阶段都单独设计、验证和提交；不得把本阶段视为完成全局 UI 改版。

## 架构边界

- 视觉 token 只属于 UI 层，不能进入播放控制器、会话持久化或 mpv option。
- Theme API 继续使用 `AppearancePreferences::Theme`；Theme 选择由现有菜单和 QSettings 负责，本阶段不改变保存格式。
- 组件继续读取 QPalette、对象名和少量语义属性；样式生成不遍历媒体帧、不订阅播放进度，也不执行 I/O。
- GUI 资源继续在 GUI 线程创建和更新。矢量图标按设备像素比绘制，避免低分辨率缩放模糊。
- Wayland 下保留 Qt 原生顶层窗口与系统装饰；不依赖 X11-only 定位、阴影或窗口管理器能力。

## 验收与验证

- 深色、浅色和跟随系统主题均能启动；Dark/Light 的主窗口表面与禁用、选中、焦点状态一致且有足够对比度。
- 欢迎区、播放列表和传输栏在 16:9 桌面尺寸、较窄窗口及 1.75 倍缩放下不发生文字裁剪、按钮挤压或控件漂移；现有最小点击目标保持不变。
- 中文和英文均能正确显示，主题运行时切换不残留旧颜色；本阶段不声称完成其他对话框的热翻译。
- `appearance-preferences`、`ui-surface` 和 `code-size` 回归通过；Debug 全量构建、Clang 格式检查、`git diff --check` 通过。按用户此前要求，本阶段不把窗口行为测试作为默认门槛；如样式契约可用非窗口测试覆盖，优先覆盖。
- 在真实 Wayland 桌面检查至少深色主题的首页和播放态截图；Xvfb 截图仅用于布局/回归参考，不作为 Wayland、GPU 或窗口行为证明。记录未能实机检查的主题、分辨率或交互，不以构建通过替代视觉验收。
- 任何样式改动不得改变队列、播放位置、解码路径、HDR 输出或视频帧性能；无需也不应引入 CPU 帧回读。

## 设计自审

- 首阶段范围已与首页内容重构、播放态重排和偏好对话框分开，后续不会被误报为已完成。
- `Theme::System`、高 DPI、Wayland 原生窗口和中文字体回退均有明确约束。
- 现有 QAction/播放行为是唯一交互来源；视觉 token 不承担业务或持久化职责。
- 验收项区分自动化样式契约、真实 Wayland 视觉检查和未覆盖的窗口行为，避免将 Xvfb 或构建成功过度解释。
